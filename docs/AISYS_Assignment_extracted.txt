1 Purpose and objective
Develop an RFID-enabled library solution that integrates with an existing Integrated Library Management
Software system without changing, deleting, or corrupting existing records. The software must support library
operations, RFID workflows, reporting, data migration, testing, documentation, offline maintenance, and user
training.
The candidate team must translate these requirements into a modular prototype and a production-oriented
implementation plan. Where an external device, vendor SDK, existing database schema, or live service is
unavailable, the team must define an adapter interface and supply a working mock.
2 Expected outcome
●
●
●
●
●
A web-based library application or demonstrable extension covering the required functional workflows.
An RFID integration or middleware service with mock adapters for staff readers, handheld readers,
security gates, smart cards, cameras, email, SMS, and print services.
A controlled migration utility for approximately 20,000 source records supplied in spreadsheet format.
A requirements traceability matrix, architecture package, test evidence, deployment guide, administration
guide, user guide, and demonstration.
A solution that can be activated, updated, upgraded, and supported in an offline or isolated environment.

9 Standard operating procedure
Follow the stages below in order. Each stage ends with a reviewable output. Do not begin production-style
integration until the preceding review is complete.
Stage 1 Initiation and controls D0
●
●
●
●
Create the repository and issue tracker.
Read this assignment and build the first requirements traceability matrix.
Record assumptions, questions, risks, dependencies, and excluded work.
Confirm that all data and credentials are synthetic.
Stage 2 Requirements and design D1 to D2
●
●
Prepare use cases and acceptance criteria.
Define the domain model, database schema, APIs, event model, integration contracts, security controls,
and deployment topology.
●
●
Create mock contracts for unavailable ILMS and RFID interfaces.
Hold a design review and record decisions.
Stage 3 Foundation build D3
●
Implement project structure, configuration, authentication, role management, audit logging, health checks,
database migrations, and test framework.
●
●
Prepare synthetic seed data and a repeatable local build.
Run static checks and baseline tests.
Stage 4 Core library functions D4 to D5
●
●
●
Implement cataloguing, members, circulation, fines, restrictions, search, reporting, and dashboards.
Demonstrate key user journeys and record defects.
Update the traceability matrix and API documentation.
Stage 5 RFID middleware and integrations D6
●
●
●
●
Implement device-neutral commands and event handlers.
Add NCIP 2.0 and SIP2 adapter boundaries with mocks.
Implement tagging, inventory, gate-event, notification, smart-card, and camera workflows.
Test retries, timeouts, duplicate events, and offline behaviour.
Stage 6 Migration and resilience D7
●
●
●
●
Profile the sample spreadsheet.
Run validation and dry-run import.
Reconcile counts and errors.
Execute migration into the test database, then demonstrate rollback and restore.
Stage 7 Verification D8
●
Run functional, integration, regression, performance, security, migration, backup, restore, offline-update,
and rollback tests.
●
●
Map every test result to a requirement.
Triage defects by severity and retest fixes.

10 Engineering controls
Control Required practice
Version control Use feature branches and reviewed merge requests. Keep
meaningful commits. Tag the final evaluation release.
Code quality Apply formatter, linter, static analysis, dependency scanning,
and automated tests in the build pipeline.
Configuration Keep environment-specific values outside source code.
Supply a sample configuration without secrets.
Secrets Do not commit passwords, tokens, certificates, private keys,
or real personal data.
Data protection Use synthetic data. Mask logs. Apply least privilege. Record
every administrative and circulation action.
Dependencies Pin versions and provide a software bill of materials with
licence and offline-installation notes.
Defects Record severity, reproduction steps, owner, status, fix
version, and retest evidence.
Change control Update the requirement, design, code, test, and
documentation together when behaviour changes.
